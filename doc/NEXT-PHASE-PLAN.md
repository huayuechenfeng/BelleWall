# 下一阶段：MP4、横屏、非标准屏与英语界面

当前基线为 1.0.2。用户反馈 E7 竖屏播放效果很好；尚无客观帧率或完整测试日志。E7 从竖屏切到横屏时壁纸会崩溃。603 的本轮视频与 C／E／F 盘测试尚待反馈。以下改动进入新测试候选，不回写 1.0.2 正式包。

**1.1.0 测试候选进度：** 已实现 MP4 向前逐帧移动与定位回退、RGB565 优先取帧、可选 GOP、导入缓冲区复用、按实际桌面尺寸重建缓存、方向与缩放策略、旧网页兼容与响应式回调，以及手机／制作工具双语。编译、离线测试和浏览器验收结果随候选保存；实际导入速度、MP4 流畅度、E7／603 旋转恢复仍待用户统一验收，E6 无实机结论。安装方法和测试清单见 [1.1.0 测试候选](CANDIDATE-1.1.0.md)。下文保留阶段目标与验收要求，不能视为已取得的设备结果。直接导入裸 MP4 尚未实现，本轮通过 MP4 SYWP 使用压缩视频。

用户还反馈 360×640、30 fps 的 SYWP 文件很大、导入很慢。原因是现有视频 payload 和手机内部 BWV2 都是无压缩 RGB565：每帧 460,800 字节，每秒约 13.2 MiB，10 秒约 132 MiB；256 MiB 包上限大约只容纳 19 秒。当前导入会边校验 SHA-256 边把 payload 复制成 BWV2，因此还要写出一份近似同样大小的文件。MP4 可缩小传输与存储量，但手机端必须能持续解码并把帧送入共享位图，不能只修改扩展名或导入界面。

## 1. 压缩视频与导入速度

先量化 E7、603 在 360×640、20／30 fps 下的 SYWP 体积、导入耗时、目标盘写入量、播放帧率与内存。把导入耗时拆成读取、写入、SHA-256 计算与提交，比较 C／E／F 盘，确定真正瓶颈。1.0.3 原型采用便携 FFmpeg 可编码的 MPEG-4 Part 2／MP4V，并通过手机系统接口把帧交给现有 FBS 绘制链；需记录解码耗时、CPU、循环、暂停／恢复、定位精度和出错后的桌面恢复，再决定是否扩展 H.264 支持。若某设备不能稳定解码，保留原始帧 SYWP 作为兼容回退，并明确告知支持范围。

在可行性成立后增加两条入口：直接导入符合手机支持配置的 `.mp4`，以及导入包含 MP4 payload 的 `.sywp`。两条入口共用媒体结构与编码检查、解码和播放时钟；直接 MP4 默认不做全文件 SHA-256，用读取／写入长度、媒体结构检查及临时文件原子提交避免半成品入库，去重哈希只在实测收益足够时使用。SYWP v1 仍按已发布的容器规范校验内置 SHA-256，且继续边复制边计算，不增加第二遍读取。压缩数据写入所选 C／E／F 盘后原子提交库记录，失败或取消后清理临时文件。显示预估空间、已写入量与进度。保留旧 RGB565 SYWP 和 BWV2 的读取能力；不在手机上先解压成巨大的帧流。视频壁纸不播放音轨，制作工具应明确处理或移除音轨。

为 SYWP 制定独立的 **MP4 视频载荷规范**：如果沿用容器 v1，就保留其已定义的头部、长度和 SHA-256 校验，用新的 `requiredFeatures` 值及明确的编码／容器字段区分 MP4 与 `rgb565le`；如果实测证明全文件哈希仍是主要瓶颈，再评估新 major 的完整性规则，不能在 v1 中悄悄取消校验。规范还需规定完整 MP4 payload 的边界、允许的编码与封装配置、画布与帧率元数据如何同媒体实际内容核对、时长／大小上限、音轨策略、循环和暂停语义、损坏文件拒绝规则，以及旧版读者的明确拒绝行为。先通过 E7、603 的解码原型确定可承诺的编码档位，再把字段与兼容规则写入 [SYWP 格式规范](SYWP-FORMAT.md) 并增加 PC 制作、检查、手机导入的一致性测试；不得悄悄把旧的 `pixelFormat: rgb565le` 重解释为 MP4。

验收：同一源视频分别制作旧帧流 SYWP、直接 MP4 与 MP4 载荷 SYWP，比较文件大小、导入时间、占用空间、持续帧率及循环／暂停／旋转恢复；在 C、E、F 盘测试取消、空间不足、损坏媒体和重复导入。记录 E7、603 的实测值，不把 30 fps 请求上限当成解码结果。

## 2. 横屏切换和恢复

先在 E7 复现并保存应用、原生进程、渲染插件日志与屏幕尺寸序列。旋转发生时暂停供帧与脏区发布，确认旧的 FBS 共享位图、缓存句柄和背景控件是否还有效；随后按新尺寸重建缓存和坐标映射，再恢复播放。重建失败应停止播放并完成桌面恢复，不能让桌面插件持续访问旧句柄。

当前固定尺寸入口包括 `renderprepare.h` 的启动准入、`sharedwallpaper.h` 的 Cache IPC 与位图、`redrawtransport.h` 的脏区边界、`renderprobe.cpp` 的背景矩形检查，以及 `candidate.h` 的首帧。逐处改为由实际桌面背景控件和显示设备协商尺寸；保留固件布局的结构核验和未知固件安全拒绝。横屏视频先定义清楚拉伸、适配或裁切策略，再处理用户包的方向声明。

验收：E7 连续执行竖屏→横屏→竖屏、锁屏／解锁、切前后台、停止恢复；对 20 与 30 fps 样本都检查无崩溃、无旧画面残留、原生壁纸恢复、共享句柄和内存不持续增长。记录实际尺寸与帧率，不能把请求上限当成实测值。

## 3. 非标准屏，包括 E6

把屏幕尺寸、源帧尺寸、绘制目标矩形和脏区分成独立参数，移除播放路径中的 360×640 断言。按照 SYWP 中已有的方向与适配字段处理不同宽高比，并为缓存 IPC 和目标位图建立尺寸匹配规则。制作工具已有 640×480 等画布预设，但目前手机端会拒绝相应尺寸或横屏声明；启用前先用 ROM、模拟输入和实机记录确认 E6 的桌面背景布局、可用画面区域与内存上限。

验收：桌面背景尺寸不等于 360×640 时也能启动、播放、旋转、暂停和恢复；不同长宽比不会越界或把图标层覆盖；不满足结构或资源检查时显示可诊断的错误并安全恢复。E6 的最终兼容结论需要 E6 实机验证，离线通过只记为候选。

## 4. 手机和 PC 工具英语适配

集中手机界面的用户可见字符串，按系统语言选择中文或英语，无法识别的语言回退到英语；将错误码和诊断术语保留稳定编号。PC 制作工具提供显式的中文／English 切换，覆盖表单、画布预设、进度、错误、能力提示、教程入口和生成包的说明。SYWP 格式与内部键名保持不变。

验收：两种语言下完整走通导入、预览、播放、停止恢复、C／E／F 盘选择及诊断；检查 E7 小屏上的截断、英文字段长度和中文回退；PC 工具测试语言切换后表单值与制作结果不变。

## 顺序与发布门槛

先测 MP4 解码可行性和现有导入瓶颈，同时处理 E7 旋转的生命周期与安全恢复；解码可用后实现直接 MP4 和 SYWP MP4 载荷，再抽取通用尺寸并验证 E6，最后完成英语界面。播放链、格式规范与制作工具须作为同一个候选一起验收，不能先发布仅能制作而手机无法播放的 MP4 SYWP。每一步生成 `dist/test/<版本>/` 候选并保留 `build/checkpoints/` 的完整验证快照。只有确定交付版本、记录离线验证和适用设备范围后，才将文件放入 `dist/release/<版本>/` 并上传 GitHub Release；测试包和构建快照不作为正式 Release 附件。
